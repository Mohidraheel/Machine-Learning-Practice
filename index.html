Abstract

5-sentence summary

This study asks which (client, content) pairs in the FlyRank search warehouse are growing, declining, recovering, or worth manual review in organic search performance — and what a content editor should do about each one. Using Google Search Console signals from October–December 2025 as features and January–March 2026 click changes as labels, a Random Forest classifier was trained on 110,933 content pairs with a grouped split that prevents the same pair appearing in both train and test. The model achieves 0.802 accuracy against a majority-class baseline of 0.600, a lift of +0.202, with strong performance on worth_review (F1 0.93) and growing (recall 0.76). Results are directional and decision-support in nature — they support prioritization of a content team's refresh capacity, not causal claims about search algorithms. The output is a ranked action playbook: 4,411 declining pairs flagged for improvement, 7,341 growing pairs flagged for protection, and 14,193 pairs recommended for manual review.

Introduction

The problem this work supports

Content teams managing large portfolios cannot review every page every month. Without a systematic prioritization signal, editors default to recency, gut feel, or random sampling — all of which miss pages that are quietly losing organic clicks.

This work builds a scoring engine that classifies each (client, content) pair into one of four categories based on its recent GSC trajectory: declining, growing, recovering, or worth review. Each prediction comes with a reason code — so an editor doesn't just know what to prioritize, but why.

The cost of a wrong call is real but asymmetric: a false "declining" flag wastes editor time on a healthy page; a missed "declining" pair keeps losing clicks unnoticed. Honest recall numbers for each class are reported so users can calibrate accordingly.

Data

Which data, which windows, what was excluded

Source

FlyRank ML Internship warehouse — table fact_content_daily_performance, accessed via hf://datasets/FlyRank/internship-warehouse.
Grain: one row = one (client_hash_id, content_hash_id) pair on one report_date.

Three date windows

  • Pre window (2025-07 to 2025-09) — earlier baseline, used only to detect a reversal for the "recovering" label
  • Window A (2025-10 to 2025-12) — feature window (16,712,226 rows). Everything the model sees comes from here
  • Window B (2026-01 to 2026-03) — label window. Used only to compute percent change in clicks, never fed to the model as a feature

Excluded and why

  • 2026-06 — sealed month, never touched even for validation
  • 2025-01 to 2025-06 — thinner GSC coverage and effectively zero GA4 coverage; mixing inconsistent data availability would hurt signal quality
  • GA4 fields — coverage 0.44% to 4.21% across the study window, too sparse to use as core features
  • client_hash_id / content_hash_id — pseudonymous identifiers used only for grouping, never as model inputs

Public-safe: no client names, domains, URLs, or raw exports appear anywhere — only hashed IDs and aggregated numeric signals.

Methodology

Assumptions, features, labels, validation

Label definition

  • growing — clicks in B > clicks in A by more than 20%
  • declining — clicks in B < clicks in A by more than 20%
  • recovering — was declining Pre→A (down >10%), turned upward A→B (up >5%)
  • worth_review — everything else: flat, or high impressions with weak CTR

Features (Window A only — no future leakage)

  • ctr — clicks / impressions across Window A (top signal, see feature importance)
  • total_impressions — total search appearances across Window A
  • position_volatility — standard deviation of daily avg position
  • avg_position — average search ranking position
  • active_gsc_days — number of days with GSC data present
  • volume_tier — low / med / high impression bucket (one-hot encoded)

Baseline

Always predict "worth_review" (majority class). Accuracy: 0.600. No model required. Every model result is measured against this floor.

Validation design

GroupShuffleSplit (75/25) grouped by (client_hash_id + content_hash_id) — the same pair never appears in both train and test. Random shuffling would inflate results by leaking page-level patterns across the split.

Leakage checks

  • clicks_b used only to compute the label, never as a feature
  • IDs are grouping keys only — an assert confirms they never enter the feature matrix
  • Pre-computed trend columns excluded — they are label-derived

Limitations

What this work cannot claim

Directional, not causal Results are observed, directional, decision-support signal only. A page's clicks can shift for reasons entirely outside the page itself — seasonality, SERP layout changes, competitor moves. No claim is made about Google's ranking algorithm.
Recovering class is unreliable Only 1.2% of pairs (1,303 of 110,933) are labeled "recovering." The model's recall of 0.02 for this class means it cannot be used as a high-confidence signal. Treat recovering predictions as a watch list only.
Declining recall is 0.59 About 4 in 10 genuinely declining pages are missed. Use the ranked output as a prioritization tool, not a complete audit of every declining page.
GA4 excluded — too sparse GA4 coverage ranges from 0.44% (2025-10) to 4.21% (2026-03). Including it would make most rows null. A future pass could add GA4 features for the subset where ga4_data_available IS TRUE.
Base rate context The majority class (worth_review) is 62.8% of all pairs. A model that always guesses worth_review scores 0.600 accuracy. The model's 0.802 is real lift (+0.202), but this context must accompany any headline accuracy number.

Ranked Recommendations

The action playbook

Sorted by priority. An editor works through declining first, then uses reason codes to decide whether to rewrite content, fix metadata, or investigate ranking instability.

Priority 1 — High
declining  Improve / Rewrite
4,411 pairs predicted declining. Check reason code: "High position volatility" → investigate ranking instability first. "High impressions, underperforming CTR" → fix title/meta description. "Stable trend, low volume" → consider merging or pruning.
Priority 2 — Medium
growing  Protect
7,341 pairs predicted growing. Leave these alone unless there is a specific reason to intervene. Monitor for cannibalization from other pages in the same client portfolio. Avoid disruptive rewrites.
Priority 3 — Medium (low confidence)
recovering  Monitor
39 pairs predicted recovering in the test set. Treat as a watch list only — recovering recall is 0.02, so most genuine recoveries are missed. Confirm trend continues before investing further.
Priority 4 — Low
worth_review  Manual Review
14,193 pairs. The model is most confident here (F1 0.93). These are candidates for merge, prune, or simply leave alone. High impressions + low CTR → metadata review. Low everything → prune candidate.

Reason code breakdown

Reason codeWhat it meansSuggested action
High impressions, underperforming CTR Page ranks and gets seen but users don't click Rewrite title tag and meta description
High position volatility — unstable ranking Position fluctuates heavily across the window Investigate content quality and topical authority
Stable trend, low volume Consistent but low traffic — not a ranking problem Consider merge with related content or prune
